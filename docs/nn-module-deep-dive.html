nn.Module 精读笔记

五件套：__init__ 属性表 / __setattr__ 路由 / _apply / state_dict / 四类 hook。以 PyTorch 2.x 源码为准，个别字段在不同小版本有增删。

01__init__ 到底建了什么

每个 Module 实例初始化后，__dict__ 里躺着这些由基类写入的字段。它们全部通过 super().__setattr__ 写入，绕过了你自己的路由逻辑——这就是不调 super().__init__() 必崩的原因。

四张数据表

字段类型作用
_parametersdictname → Parameter，优化器从这里拿东西
_buffersdictname → Tensor，不训练但要存要迁
_modulesdictname → Module，子树
_non_persistent_buffers_setset不进 state_dict 的 buffer 名字集合

一个状态标志

trainingbool初始 True。train()/eval() 递归改写它，Dropout / BatchNorm 在 forward 里自己读它决定行为

十二组钩子字典

全部是 OrderedDict：既保证执行顺序，又能按 handle 精确删除。

字段触发时机
_forward_pre_hooksforward 之前，可改写输入
_forward_pre_hooks_with_kwargs同上，但带 keyword 参数
_forward_hooksforward 之后，可改写输出
_forward_hooks_with_kwargs同上，带 kwargs
_forward_hooks_always_called标记哪些 hook 即使抛异常也必须调用
_backward_pre_hooks反向传播到达本模块之前
_backward_hooks反向传播经过本模块之后
_is_full_backward_hook标志位，区分新旧两种 backward hook 语义
_state_dict_pre_hooks保存前
_state_dict_hooks保存后，可改写产出的 dict
_load_state_dict_pre_hooks加载前，可改写待加载 dict
_load_state_dict_post_hooks加载后，可改写 incompatible_keys

一个编译缓存

_compiled_call_impl：torch.compile 命中后，__call__ 会直接走这个预编译版本，跳过动态 hook 检查以降低 Python 开销。

验证方式：print(sorted(m.__dict__.keys()))。不同版本字段数会变，理解"分四类：表 / 标志 / 钩子 / 缓存"比背数字有用。

02__setattr__ 的三岔路由

这是 nn.Module 唯一真正的"魔法"。每一次 self.xxx = value 都在被分类：

def __setattr__(self, name, value):
    def remove_from(*dicts_or_sets):
        for d in dicts_or_sets:
            if name in d:
                if isinstance(d, dict):
                    del d[name]
                else:
                    d.discard(name)

    params = self.__dict__.get('_parameters')
    if isinstance(value, Parameter):
        # 岔路一：参数
        remove_from(self.__dict__, self._buffers, self._modules,
                    self._non_persistent_buffers_set)
        self.register_parameter(name, value)

    elif params is not None and name in params:
        # 已经注册为参数的名字，只允许赋 None（=注销）
        if value is not None:
            raise TypeError(f"cannot assign '{torch.typename(value)}' as parameter '{name}'")
        self.register_parameter(name, value)

    else:
        modules = self.__dict__.get('_modules')
        if isinstance(value, Module):
            # 岔路二：子模块
            remove_from(self.__dict__, self._parameters, self._buffers,
                        self._non_persistent_buffers_set)
            modules[name] = value
        else:
            buffers = self.__dict__.get('_buffers')
            if buffers is not None and name in buffers:
                # 岔路三：替换已有 buffer
                if value is not None and not isinstance(value, torch.Tensor):
                    raise TypeError(f"cannot assign '{torch.typename(value)}' as buffer '{name}'")
                buffers[name] = value
            else:
                # 默认：普通属性，PyTorch 完全不管
                object.__setattr__(self, name, value)

四条推论

  1. 普通张量会静默漏掉：self.w = torch.ones(3) 走最后一支，不进任何表 → 不在 parameters()、不进 state_dict、不随 .to() 迁移。不报错，是纯静默失败。
  2. 同名会互踢：remove_from 会把同名项从其他表里删掉。所以一个名字只能属于一张表，先设参数再设 buffer 同名，前者会消失。
  3. 赋 None 是"注销"：self.w = None 对已注册的参数会把它从 _parameters 里移除（值置 None），这是官方支持的临时禁用层的手法。
  4. 读的时候有兜底：__getattr__ 依次查 _parameters → _buffers → _modules，都没找到才抛 AttributeError。
反模式：直接操作 self._parameters['w'] = ...。绕过了类型检查和互踢逻辑，容易造出"幽灵参数"——它在表里但不在 __dict__，或者反过来的。永远用 register_parameter / register_buffer。

03_apply：设备与精度的唯一引擎

.to() / .cuda() / .cpu() / .float() / .half() / .bfloat16() 全都只是薄封装，真正干活的是 _apply(fn)：

def _apply(self, fn, recurse=True):
    if recurse:
        for module in self.children():
            module._apply(fn, recurse)

    for key, param in self._parameters.items():
        if param is None:
            continue
        with torch.no_grad():
            param_applied = fn(param)          # 生成新张量
        param_grad = param.grad
        ...
        param.data = param_applied             # 只换底层 storage！
        if param_grad is not None:
            param.grad = param_grad

    for key, buf in self._buffers.items():
        if buf is not None:
            self._buffers[key] = fn(buf)       # buffer 直接被替换成新张量

    return self

to() 里的那个细节

def convert(t):
    if convert_to_format is not None and t.dim() in (4, 5):
        return t.to(device, dtype if t.is_floating_point() or t.is_complex() else None,
                    non_blocking, memory_format=convert_to_format)
    return t.to(device, dtype if t.is_floating_point() or t.is_complex() else None,
                non_blocking)

注意 dtype if t.is_floating_point() else None：整数 buffer 只换设备、不换精度。所以 BatchNorm 的 num_batches_tracked（int64）不会被 .half() 变成 fp16。

三个必知的坑

  1. Parameter 对象本身没变（只换了 .data），所以 optimizer = Adam(model.parameters()) 在 .to(device) 之后依然有效。这是设计上的正确性保证。
  2. 但 optimizer 的 state 不会跟着搬：Adam 的 exp_avg / exp_avg_sq 还在旧设备。跨设备恢复训练必须手动迁，否则报 "expected all tensors on same device"。
  3. buffer 是被替换而非原地改：如果你在别处持有 buf 的引用（比如某个 hook 里存了），.to() 之后那个引用指向的是旧张量，已经失效。
进阶开关：torch.__future__.set_overwrite_module_params_on_conversion(True) 会让 .to() 创建新的 Parameter 对象而不是改 .data。这样做之后老的 optimizer 就失效了——这是"我希望换设备后重新建优化器"场景下的显式选择。

04state_dict 的存取规则

生成规则

def _save_to_state_dict(self, destination, prefix, keep_vars):
    for name, param in self._parameters.items():
        if param is not None:
            destination[prefix + name] = param if keep_vars else param.detach()
    for name, buf in self._buffers.items():
        if buf is not None and name not in self._non_persistent_buffers_set:
            destination[prefix + name] = buf if keep_vars else buf.detach()

def state_dict(self, destination=None, prefix='', keep_vars=False):
    self._save_to_state_dict(destination, prefix, keep_vars)
    for name, module in self._modules.items():
        if module is not None:
            module.state_dict(destination, prefix + name + '.', keep_vars)
    return destination
  1. 顺序：先自己的参数，再自己的 buffer，然后递归每个子模块。所以键序是"参数 → buffer → 子树"。
  2. 键名：prefix + name，子模块的前缀自动拼接，得到 blocks.0.attn.qkv.weight 这种路径。
  3. 值是引用：keep_vars=False 时取 .detach()，仍共享同一份 storage。要留快照必须 copy.deepcopy，否则后续训练会改掉你的"存档"。
  4. 跳过 persistent=False 的 buffer：可通过 register_buffer(name, t, persistent=False) 排除。

加载规则

def load_state_dict(self, state_dict, strict=True, assign=False):
    ...
    def load(module, local_state_dict, prefix=''):
        module._load_from_state_dict(local_state_dict, prefix, local_metadata,
                                     True, missing_keys, unexpected_keys, error_msgs)
        for name, child in module._modules.items():
            if child is not None:
                child_prefix = prefix + name + '.'
                load(child, {k: v for k, v in local_state_dict.items()
                             if k.startswith(child_prefix)}, child_prefix)
    ...
    if strict:
        if unexpected_keys: error_msgs.append(...)
        elif missing_keys:  error_msgs.append(...)
    if error_msgs: raise RuntimeError(...)
    return _IncompatibleKeys(missing_keys, unexpected_keys)
  • 默认是 copy_ 语义：把值拷进已有的参数张量，形状必须匹配。
  • assign=True：直接替换 Parameter 对象，形状可以不同。配合 meta device 做延迟初始化时必备。
  • strict=True 同时检查两个方向：missing_keys（模型有、文件没有）和 unexpected_keys（文件有、模型没有）。

报错对照表

报错真正原因
Missing key(s)模型里新增了层，或保存时用了 DataParallel 前缀 module. 而现在没有
Unexpected key(s)文件里的结构和当前模型不一致；常见于改了 ModuleList 的顺序或层数
size mismatch改了 num_embeddings / 分类头类别数；只能靠 strict=False 跳过或重新初始化该层
加载后指标全崩最常见：忘了 model.eval()，或 key 顺序对了但语义对错了（例如把 qkv 拆分方式改了）
工程习惯：checkpoint 里只存 state_dict + 一个独立的 config.json，不要 torch.save(model)。前者可移植、可跨版本、能被 safetensors 加速；后者把类路径腌进文件，重构代码就废了。

05四类 hook

前向与反向

注册方法回调签名能做什么
register_forward_pre_hook(module, args) → new_args改写输入（如统一 dtype、插噪声）
register_forward_hook(module, args, output) → new_output抓特征、改写输出（如量化反量化）
register_full_backward_pre_hook(module, grad_output) → new_grad_output梯度进模块前拦截（梯度裁剪）
register_full_backward_hook(module, grad_input, grad_output) → new_grad_input梯度出模块后改写

另有四个 state_dict 钩子：register_state_dict_pre_hook / register_state_dict_post_hook / register_load_state_dict_pre_hook / register_load_state_dict_post_hook。LoRA、量化、权重名映射全靠它们做"键名翻译"。

执行顺序

__call__ → _call_impl:
  1. 全局 forward_pre_hook          (register_module_forward_pre_hook)
  2. self._forward_pre_hooks        ← 可返回新 args
  3. self.forward(*args)            ← 你写的方法
  4. self._forward_hooks            ← 可返回新 output
  5. 全局 forward_hook

实战片段

import torch, torch.nn as nn

# 抓每一层的输出统计，不用改模型代码
def stat_hook(name):
    def fn(module, args, output):
        if isinstance(output, torch.Tensor):
            print(f"{name:24s} {tuple(output.shape)} "
                  f"mean={output.mean():.3f} std={output.std():.3f} "
                  f"nan={torch.isnan(output).any().item()}")
    return fn

handles = [m.register_forward_hook(stat_hook(n))
           for n, m in model.named_modules() if len(list(m.children())) == 0]

model(x)
for h in handles: h.remove()      # 一定要卸，否则重复调用会越积越多

# 梯度范数监控（反向）
def grad_hook(name):
    def fn(module, grad_input, grad_output):
        g = grad_output[0]
        if g is not None:
            print(f"{name:24s} grad_norm={g.norm():.4g}")
    return fn

三个约束

  1. full_backward_hook 不能改 forward 的中间变量，只能改流入的梯度；且模块里有 inplace 操作时会直接报错。
  2. hook 必须 remove：返回的 handle 不卸载会一直累积，长训练里既慢又容易内存泄漏。
  3. 不要重写 __call__：那会绕开 ①②④⑤ 全部钩子，让所有依赖 hook 的工具（profiler、量化、梯度检查点）失效。要定制行为就写 forward。
