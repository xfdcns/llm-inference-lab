01P1 地基：CUDA 与性能分析（W1–W3，11/16–12/06）

周次主题具体动作验收标准
W1
11/16		 CUDA 模型 grid / block / warp 三级结构；global memory 访问合并；写 vector add、矩阵转置（naive → shared memory tiled 两版） 能解释为什么 tiled 转置能让 dram 吞吐上去；两版都能跑通并测出时间差
W2
11/23		 三类 kernel warp 内 reduction（用 __shfl_down_sync）、数值稳定的 softmax（online 版）、tiled matmul softmax 用 ncu 证明是 memory-bound；tiled matmul 比 naive 快 3 倍以上
W3
11/30		 Profiling nsys 看一次推理请求的时间线；ncu 抓 attention kernel 看 stall reason；手算 roofline 能写出：「该 kernel 的 arithmetic intensity 约 X，落在 roofline 的 memory 侧，所以优化方向是减少 HBM 读写而非减少 FLOPs」
环境建议：本地有 4090 / 3090 就够。装 WSL2 + CUDA 12.x + ncu（Windows 原生也能跑 ncu，但 Linux 下工具链问题少一半）。没有卡就租云 GPU，按小时计费，每天几块钱。别在这一步纠结设备，两周内必须开始写 kernel。

07七条防坑提醒

  1. 不要先学完 CUDA 再找场景。两周内必须让第一个 kernel 跑出数字，否则很容易卡在"环境配了两周"。
  2. 不要囤课。任何视频教程看到第 3 集还没动手，就停下写代码。
  3. 数字比术语值钱。简历上「吞吐提升 23%，TTFT 降低 31%」永远赢过「熟悉 vLLM 架构」。
  4. 每个结论都要有 baseline。没有对照组的"优化"在面试里会被追问到崩。
  5. 接受"只有 10% 提升"。真实系统里 10% 已经是好消息，关键是你能解释它从哪来。
  6. 研二下的科研不能停。把 agent 方向的实验和推理优化挂钩（比如测多轮 agent 的延迟构成），两边都能用。
  7. 提前一个月开始投。rolling 招聘里，岗位放出来第一周的简历通过率最高。
